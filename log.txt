1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
Offline-first gym tracker built with React Native (Expo SDK 54) + TypeScript.
Two tabs (Workout | Diet) via React Navigation bottom tabs; Add Workout and
Workout Detail are native-stack screens. All data persists locally through
AsyncStorage behind a repository layer (swappable for a real backend later).

Layer rules (keep them!):
  - screens/       UI only; never touch storage.
  - stores/        Zustand stores = the ONLY state screens talk to.
  - data/          Framework-agnostic: models.ts, repositories.ts,
                   exerciseLibrary.ts, services/storageService.ts.
  - theme/         Light/dark palettes (theme.ts), ThemeContext,
                   persisted themeStore (zustand).
  - components/    Shared UI kit (ui.tsx: Button, Card, SectionTitle,
                   ProgressBar, Field, ModalSheet, EmptyState, Stepper,
                   Segmented) + StrengthChart (Victory Native + Skia).
  - navigation/    index.tsx — tabs + stack, themed via NavigationContainer.
  - App.tsx        Hydration gate: hydrates theme/workout/diet stores before
                   rendering the navigator.

Key data concepts:
  - WorkoutSession { id, date (ISO YYYY-MM-DD), restDay, bodyParts[], createdAt }
  - Strength score = SUM(weight x reps) over all sets of a day
    (computeSessionStrength / computeStrengthSeries in data/repositories.ts).
  - Streak = consecutive workout days; marked rest days are NEUTRAL (bridge the
    chain, add nothing); a day with neither workout nor rest mark breaks it
    (computeStreak, same file). Behavior is pinned by tests/analytics.test.ts —
    do not change streak semantics without updating those tests.
  - Analytics are DERIVED from `sessions` on every render (useMemo) — there is
    no cached streak/score counter to decrement anywhere.

Commands:
  npm run typecheck   (tsc --noEmit)
  npm test            (vitest run — tests/analytics, tests/stores, tests/theme)
  npx expo start      (dev server; web via --web)

3. ACCIDENT & RECOVERY (worth knowing for future sessions)

in one call (e.g. "</Text>" became "Text>"). It was caught immediately by
grepping for lines matching /^[A-Za-z]+>\s*$/ and fixed by rewriting

a file, suspect this and re-verify the whole file.

1. BUG FIX — "Delete workout button does nothing" (user report)
--------------------------------------------------------------------------------
ROOT CAUSE (confirmed by reading node_modules/react-native-web/dist/exports/
Alert/index.js): react-native-web implements Alert as a literal no-op:

    class Alert { static alert() {} }

The trash buttons DID have onPress handlers and the store's deleteSession DID
persist correctly — but on web, Alert.alert() never renders a dialog and its
button callbacks (which contained the deleteSession call) never fire. So the
tap appeared completely dead on web. (It would have worked on native.)

FIX:
- components/ui.tsx: new <ConfirmDialog> — themed in-app Modal with
  cancel/confirm buttons, `destructive` variant, cancelLabel='' hides cancel
  for OK-only dialogs. Replaces Alert.alert everywhere.
- components/Toast.tsx (NEW): module-level showToast() + <ToastHost /> mounted
  in App.tsx inside SafeAreaProvider. Fixed bottom placement (above the tab
  bar, insets.bottom + 88). Used for: "Workout deleted", "Today marked as
  rest", "Rest day unmarked", "Workout saved" (also replaced the old
  Alert in AddWorkoutScreen save-failure path).
- screens/WorkoutHomeScreen.tsx + WorkoutDetailScreen.tsx: swapped Alert for
  ConfirmDialog state machines; delete confirms then calls deleteSession and
  toasts. Detail screen navigates back after delete (list is already current).

Delete flow is now: tap trash -> ConfirmDialog ("Delete this workout? / This
can't be undone") -> confirm -> deleteSession -> AsyncStorage write ->
toast. List/graph/streak update immediately (derived state).

2. HARDENING — rest-day rules pushed into the store
--------------------------------------------------------------------------------
stores/appStores.ts: toggleRestDay no longer silently toggles. It now returns
Promise<string | null> (error message or null) and REJECTS:
- marking a day already marked as rest ('Today is already marked as a rest
  day.') — prevents duplicate markers;
- marking a day with a logged workout ('You already logged a workout today.
  A day cannot be both.').
UI: unmark path now deletes the marker session directly (deleteSession),
which cannot collide with the guards. Store-level rejection is surfaced via
toast if it ever fires.
